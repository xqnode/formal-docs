# 结构与写作要点

按任务阅读相关小节，不把本文件变成必须逐项展开的模板；项目已有结构、人称与交付约定优先。

## 读者基础与内容取舍

先确认读者已有知识、实际经验和学习目标：理解概念、跟随完成、独立实现或排错。会 Python 不代表熟悉接口、数据库与部署；上下文不足时默认首次接触主题，不假设毫无编程基础。判断依据是前文实际讲过什么，不仅是“入门”“进阶”标签或章节编号。

每项内容应解决当前疑问或支撑当前任务，评估学习收益与新增概念、操作的负担。以跟随操作为目标的教程，先给能看到结果的最小任务，再增加必要机制；原理说明按问题、条件与因果关系展开，观点或比较文章按论证需要组织，不要求先搭环境或完成项目。权限、租户、并发、持久化和部署只按目标引入。必要的行为当场讲清，辅助细节说明用途即可，无关抽象留到相应主题。不能靠给复杂代码补长解释代替选型判断。

## 面向独立学习的实战教程与配套视频

教学主线按理解、操作、观察结果组织。视频可以补充推演与演示，不能成为补全笔记中缺失实现、步骤或解释的入口。具体运行与人工截图见 [课程笔记](course-notes.md)。

独立学习不等于必须安排练习。默认提供完整实现，练习仅在交付形式与学习目标确有需要时采用；视频配套笔记不留学员 TODO。完成跟随操作不等于能脱离引导独立设计。

## 入门操作教程

按实际主题组织任务、前提、概念、操作、结果与排错，不固定标题或步骤数量。系列首篇自然引入要学什么、先做什么；前提和验收放在相关步骤，不把背景、课程范围、目标机械拼成首段。

术语首次出现时解释它与当前操作的关系，不提前堆积定义。只用于了解文件存在的配置说明作用即可，内部机制等到使用时展开。

## 初学者的框架教程

以已有语言基础为起点，讲清新增的框架知识。比如首次接接口，先让浏览器收到回复，再接入已有流程；不要同时叠加多个陌生机制。

首次出现、承担学习目标或行为不明显的函数、语法和常量，结合具体数据讲清输入来自哪里、如何处理、输出给谁及为什么需要。涉及回调、暂停恢复、资源清理时说明谁调用、传什么值与执行顺序，不用“框架自动处理”替代过程。解释以顺着示例理解为准，不设“一两句话”的上限，也不把当前必需的解释推给后续章节。

沿用指定或已学工具，核对对应版本官方入门示例，优先常规写法。官方支持某接口不等于它适合当前教学；选择其他方案要有收益与理解成本上的理由。存在关键边界、常见误用或有教学意义的替代方案时，简短比较能否完成、为何选当前写法和误用现象，并实跑相关行为；不规定数量，不枚举所有等价写法。例如需要保留合法的 `0` 时，核对 `||` 是否错误使用默认值。

遇到“能跟着做但看不懂”，先定位缺失的前置知识、数据交接或一次引入过多机制，再补最小解释与结果推演，不只换口语词或无限增加边界处理。调整既定主线仍须遵守作者授权。

## 代码呈现与文字练习

- 按功能与实现顺序组织，不按手写、带读、复制分类。逐步增加时明确文件、新建或替换范围、输入输出、业务规则与中间核对结果；完整代码按功能说明如何接入已有实现。
- 配置、种子数据和样式等配套文件提供足够完整内容，说明作用、存放位置、运行入口和成功标准。算法不属于当前目标时说明直觉或公式，属于目标时讲清实现过程。
- 临时借用尚未系统讲解的辅助命令，只说明当前所需用途、参数、前提与行为，验证成功和失败边界，不提前引入整套机制。
- 内存示例说明停止后是否保留记录，不冒充持久化。对照代码提前注明不需要写入文件。

明确安排补全练习时，仅改造已讲行为，提供可加载骨架、目标相关 TODO、可观察验收与完整参考答案；不用无关语法错误充当反馈。分别实跑骨架与答案：同一目标检查先失败、补全后通过，按需要用有区分度的输入核对。提示给方向，不以“略”代替过程，也不把通过检查等同独立掌握。

### 教学代码的表达取舍

- 面向有语言基础的学习者，不为强调“入门”刻意展开已有的基础语法；把讲解重点放在本节新增的框架知识和业务设计。首次遇到必要的语言特性时补充说明即可。
- 主动检查手动累积、状态标志与循环查找是否适合使用语言惯用表达。Python 中可考虑 max、any、next 或字典解包等，但这些只是候选方案，不规定循环必须替换。结合返回值、短路行为、空集合、可读性与受众判断。
- 简化以语义清楚为准，保留能指出具体错误字段、体现必要处理顺序或帮助定位问题的检查；不把逐字段检查机械合并成丢失诊断信息的布尔判断。精简实现不等于省略关键分支的教学注释。
- 同一逻辑在分步示例、完整代码或其他章节出现多处时，同步修改代码、注释、讲解与示例结果；避免正文已换写法而核对代码仍保留旧实现。

### 条件分支的教学注释

- 条件判断是讲解“怎样从需求设计代码”的关键步骤。除非常简单的判断或此前代码片段已经出现并解释过的相同 if 逻辑外，每个 if 都在上方或邻近位置写明判断目的与分支处理，不只在整段代码之后补说明。
- 注释交代触发条件所表达的业务含义、为何需要该检查，以及成立后为何返回、拒绝、跳过或继续处理。只写“判断是否为空”“如果条件成立”通常不足以解释设计；例如可写“只处理本次提交的名称，未提交时保留原名称”。
- 注释直接说明具体用途、业务规则、数据来源与处理原因，不写课程章节引用或制作话术。
- 嵌套判断与关键 elif/else 分支分别评估。已经解释过的同类检查可复用，不逐字重复；完整代码核对片段保留必要注释，以便读者对照代码理解流程。
- 保持代码自然简洁，不为增加讲解点拆出多余变量或展开本可直接表达的逻辑。内置函数中的筛选条件、短路表达式若承载关键业务选择，也要解释其意图；简单重复条件无需机械加注释。

## 面向有工程经验读者的框架精讲

从实际问题、代码或故障进入，按技术关系组织条件、示例、关键行为、边界与验证。简短承接已学知识，重点解释新增机制、差异与取舍；不能因章节靠后省略首次出现的机制。

## 技术说明与局部修订

按读者需回答的问题组织适用条件、输入输出、接口约束和失败处理。局部修订保留结构，只同步必要内容；准确清楚或已认可的表达不为润色重写。

观点、比较或经验文章区分事实、经验观察与判断；比较采用一致的前提和维度，结论限定在已有依据支持的范围，不把个别经验写成普遍规律。

独立文档补全前提；系列引用须指向确实存在、读者可见的前篇文件与使用条件。不得用未提供的截图、日志或内部材料支撑正文结论。

## 系列写作与衔接

- 后续章节承接实际文件、数据与代码状态，突出新增问题、概念或操作。对照相邻标题、开头与段落，不只换主题词复用骨架，也不为制造差异强改清楚表达。必要前提放在对应操作处，不写作者讨论中的课程取舍。
- 用具体行为、条件和结果展开，删空话、重复小结与填空白的标题。同一信息集中说明；独立复制运行的代码仍保持所需上下文完整。
- 教学内容以结果核对结束，不为凑结构加小结。有下一节时，文末独立一段说明学习内容；有“本节代码下载”则放在下载说明之后，不另设预告章节。
- 正文使用“本节”“上一节”“下一节”；后两者仅指紧邻课程，跨节或有歧义时用两位编号，如“第 06 节”“第 06、07 节”。详细版、精简版与重复示例同步；代码注释遵循上方规则，不写课程引用。

## 呈现与来源

- 文件名和路径在正文、标题内用行内代码，例如 `app/api/__init__.py`；独立展示复杂路径用 `text` 围栏，避免特殊字符丢失。不在代码块内另套反引号。
- 保留围栏语言与合法 Markdown。含自然语言占位的语法示意不是可运行代码，标 `text`。标点、引号与中英文间距沿用项目约定。
- 引用优先采用对应版本官方中文资料，实际确认语言和来源。英文官方资料标“英文”，第三方补充标来源身份；不靠翻译标题或猜语言路径假装中文来源。
