# 按读者与交付选择结构

本文件是结构参考，不是必须逐项展开的模板。项目已有标题、人称和章节约定时沿用；标题只承担导航，避免把流程标签当作正文。

## 面向独立学习的实战教程与配套视频

实战教程默认支持学员只看笔记完成学习，不按教师带敲顺序或口播节奏写稿。即使有配套视频，也要在笔记中给出完整实现、操作位置与顺序、关键代码的原因、运行命令和结果判断标准。视频可以补充思路推演和排错演示，不能成为理解当前步骤的必需入口。

独立学习不意味着每节都要安排练习、TODO 填空或独立编写任务。默认给出完整实现并让读者运行核对；确需练习时，围绕已讲内容提供验收与参考答案。项目明确要求的交付形式优先，不能仅因文档名含“教程”就增加练习。

## 入门操作教程

适合需要安装、输入位置与排错说明的读者。通常包含任务与前置条件、概念和操作、可运行示例、结果核对及必要的排错说明。沿用项目的小结或结构约定；练习仅适用于独立文字教程，没有要求时按学习目标取舍。

开头自然引入主题或承接前文，系列首篇优先直接说明开始学习什么、先做什么；不强制在首段写学习目标或可验证产出。任务前提与结果核对放在相关步骤，不机械挤进开头。首次使用术语时解释它与当前操作的关系，不提前堆积定义。

## 初学者的框架教程

适合已学过语言基础、第一次接触框架的读者。先明确“已经会什么”和“这次要完成什么”；不要因为教程名称有“框架”“实战”就假设读者有后端工程经验。

先给一个能立即看见结果的最小例子，再增加本篇的核心行为。例如第一次接接口，先让浏览器收到一句回复，再接入已有处理流程；不同时安排登录、数据库、审批版本与并发控制。顺序依据实际主题选择，不固定标题或步骤数量。

每次操作写明文件名、所在目录、在哪输入、需要新建还是替换、怎样运行及哪里查看结果。首次出现的调用先交代接收什么、执行什么、返回什么，再解释术语。完整代码仍可保留，但按功能分组讲解，指出各段与前篇知识的关系；不要用“代码如下”接一大段陌生机制后结束。

工程细节分三种处理：完成当前任务必需的行为当场解释；帮助理解但不阻塞操作的细节可单独补充；与当前任务无关的机制留到相应主题。示例边界只说明读者需要判断的事实，例如重启后记录丢失、演示不会执行真实支付；不堆生产加固清单。用户已要求真实权限或持久化时，应拆成可学习的步骤，不能将这些需求删去。

技术选择优先沿用明确的用户偏好与已学工具。例如系列前篇使用 MySQL，就优先评估沿用它；这不是所有教程都必须使用 MySQL 的规定。更换工具需要具体理由和操作说明，不能只为作者省配置而增加读者的陌生概念。

独立文字教程安排练习时，只改造已讲过的行为，给出可观察的验收；提示指向知识点，答案写完整操作或代码。视频配套笔记用完整演示与结果核对呈现同类知识，不留作学员练习。遇到“看不懂、太工程化”的反馈，先检查是否跳过了前置概念或同时引入过多机制，再缩小主线任务、补操作和结果，不能只把术语换成更口语的词。

交付前人工核对：

- 读者能否找到文件、输入位置和运行入口？
- 每段新增代码是否解释了作用，以及为什么当前任务需要它？
- 代码注释是否解释了首次出现、承担学习目标或行为不明显的函数，以及非显然的常量与新语法，而没有堆积样板注释？
- 是否能根据输出或页面状态判断成功，并处理实际遇到的常见失败？
- 当前步骤是否依赖未讲过的功能？视频笔记是否误设练习？文字教程已有的练习是否超出正文知识？

## 代码呈现与文字练习

按学员完成任务所需的信息组织代码，不按手写、带读、复制给内容分类：

- 需要理解实现过程时，按功能逐步增加代码，明确每段所在文件、新增或替换范围、输入输出和业务规则；中间状态需要运行时，当场说明如何核对。
- 逐行输入没有额外学习收益时，提供完整代码并按功能解释，说明它与已有实现如何连接。首次模型或框架调用至少交代接收什么、执行什么、返回什么。
- 配置、种子数据、页面样式等配套内容可以提供完整文件，但必须交代作用、存放位置、运行入口与成功标准。算法不是当前学习目标时解释直觉或公式；算法属于学习目标时讲清实现或改造过程。

正文用自然操作说明承接代码。组织内容依据理解和操作负担，不依据教师输入耗时；不以完成跟随操作或通过检查推断学员已经能够脱离引导独立设计。

仅独立文字教程可采用补全练习：给出能加载的骨架，留下少量与本节目标相关的 TODO，不固定空缺数量或行数。先通过用途、输入输出和必要的步骤注释说明意图，再让读者完成实现；注释解释原因，不逐行复述代码，也不要求与答案逐行对应。

补全练习必须给出能验证目标行为的命令和参考答案，并分别实跑骨架与答案：骨架应能加载，指定检查因目标行为未实现而失败；填入答案后同一检查通过。失败提示帮助定位目标行为，不用无关语法错误充当教学反馈。用允许与拒绝等有区分度的输入验证行为，并按需要说明边界。可按内容选择代码解析、补全或改造练习，不强制递进到独立实现，也不把通过检查等同于独立掌握。视频课程可以演示同样的思考与验证过程，但配套笔记提供完整实现，不保留学员 TODO。

### 教学代码的表达取舍

- 面向有语言基础的学习者，不为强调“入门”刻意展开已有的基础语法；把讲解重点放在本节新增的框架知识和业务设计。首次遇到必要的语言特性时补充说明即可。
- 主动检查手动累积、状态标志与循环查找是否适合使用语言惯用表达。Python 中可考虑 max、any、next 或字典解包等，但这些只是候选方案，不规定循环必须替换。结合返回值、短路行为、空集合、可读性与受众判断。
- 简化以语义清楚为准，保留能指出具体错误字段、体现必要处理顺序或帮助定位问题的检查；不把逐字段检查机械合并成丢失诊断信息的布尔判断。精简实现不等于省略关键分支的教学注释。
- 同一逻辑在分步示例、完整代码或其他章节出现多处时，同步修改代码、注释、讲解与示例结果；避免正文已换写法而核对代码仍保留旧实现。

### 条件分支的教学注释

- 条件判断是讲解“怎样从需求设计代码”的关键步骤。除非常简单的判断或此前代码片段已经出现并解释过的相同 if 逻辑外，每个 if 都在上方或邻近位置写明判断目的与分支处理，不只在整段代码之后补说明。
- 注释交代触发条件所表达的业务含义、为何需要该检查，以及成立后为何返回、拒绝、跳过或继续处理。只写“判断是否为空”“如果条件成立”通常不足以解释设计；例如可写“只处理本次提交的名称，未提交时保留原名称”。
- 嵌套判断与关键 elif/else 分支分别评估。已经解释过的同类检查可复用，不逐字重复；完整代码核对片段保留必要注释，以便读者对照代码理解流程。
- 保持代码自然简洁，不为增加讲解点拆出多余变量或展开本可直接表达的逻辑。内置函数中的筛选条件、短路表达式若承载关键业务选择，也要解释其意图；简单重复条件无需机械加注释。

## 面向有工程经验读者的框架精讲

从实际问题、代码或故障进入，按技术关系命名小标题。一般顺序是问题与条件、完整示例、关键行为与边界、验证或改造；不固定标题、段数或错误条数。

连续文章先核对上篇留下的文件与状态，再明确本篇新增或替换的部分。结尾用必要的行为结论收束，简短说明后续范围，不重复整篇内容。

## 技术说明与局部修订

技术说明按读者需要回答的问题组织，例如适用条件、输入输出、接口约束、失败处理。局部修订保留现有结构，只同步必要的术语和交叉引用。

独立文档补足全部前提；系列章节可以引用已存在的前篇材料，但要给出文件与使用条件。不要伪造相对路径，也不要因为要求“正式”就复制大段已有代码。

## 流程与关系图

调用顺序、数据流等知识点按读者需要主动配 SVG，是否画图及文件引用、配色、范围和渲染检查统一遵循 [图解辅助理解](diagrams.md)，不为固定文章结构凑图。

## 结果与交叉引用

- 可运行示例给出实际命令、运行目录和可核对的结果；不能运行的说明标注为示意。
- 真实输出保留原样。随机 ID、时间与模型措辞说明变化范围，验收只断言稳定行为。
- 独立文字教程安排练习时，明确产出与验收；提示给方向，答案提供足够完成任务的过程，不采用“略”。视频配套笔记保留演示验证，不设置练习与答案。
- 修改路径、编号、字段或结果时，同时核对引用、示例，以及文字教程已有的练习与答案。
- 后续内容只说明范围，当前步骤不能依赖尚未介绍的接口或代码。
