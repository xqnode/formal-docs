# 课程笔记约定

教学结构、概念引入与代码讲解见 [结构参考](structure-template.md)。本文件按任务读取：实现步骤看“操作与运行”，需要人工图片看“人工截图”；不将全部运行提醒作为每节模板。

## 操作与运行

- **操作完整**：写明本节新增或变化的操作目录、文件路径、界面入口、具体输入和执行顺序；代码明确新建、替换或追加的位置与范围，命令明确执行目录。只在影响本节操作或结果时说明重启、刷新或状态重置，并写清原因；例如需要重新编译图、排除历史对话影响。系列已讲过的常规启动可以简写，验证保留具体输入、结果查看位置与判断标准。

- **常规提醒不重复强调**：系列后续章节不反复强调已讲过的终端兼容、登录、刷新、新对话、等待上一轮结束或虚拟环境激活提示，例如“npm.ps1 被阻止时使用 npm.cmd”。这些内容集中放在首次环境配置或对应排错位置；只有当前引入了新的前提、实际阻断或不说明会影响结果时才补充，不把通用操作提醒拼成每节固定段落。

- **判断标准完整**：每个关键步骤给出在哪里看结果、必须一致的字段或条件、允许变化的部分及成功/失败标准。模型措辞、SQL 排版、时间或随机值可以变化，商品对象、统计口径、关键筛选条件和协议结构按实际要求核对；不能要求画面或生成代码逐字相同。常见失败写明先查看哪个页面、控制台或日志，以及如何继续处理。复杂 SQL 或长输出用代码块保留，截图只证明选定的关键运行效果，不代替操作说明与判断标准。

- **默认使用 Windows**：未另行指定时，教程的本机安装、配置、操作步骤和命令以 Windows 为基线，终端命令默认使用 PowerShell；在相关步骤注明必要的系统或终端版本，不为此给开头增加固定声明。不主动补充 macOS、Linux 的安装分支、命令对照或下载入口。用户明确要求其他系统，或技术与任务本身依赖特定平台（如 Linux 服务器部署）时，按实际平台编写。文件名大小写等行为按目标文件系统说明，不声称大小写错误一定会在本机报错。

- **全新环境的默认行为**：独立教程或首次环境配置按全新安装的系统推演主线步骤；系列后续章节沿用已经完成的环境，不逐节重复兼容提示。默认设置下大概率出现的阻断（例如 Windows PowerShell 默认禁止运行脚本，导致 `npm` 无法执行）放进主线处理，不留到文末常见问题；后文的操作指引与选定的处理方式保持一致。命令必须在读者实际使用的终端里实测，选项能否传到目标程序也要核对（例如经包管理器转发选项的 `--` 写法，在某些 Windows 终端里可能丢失选项），实测不通过就换用不需要转发的写法，并在正文说明现象与处理办法。

- **报错位置与原文**：展示报错前，先说明它在哪里出现、怎么打开。区分编译期错误（如 Vite 在页面上显示错误提示）和运行时错误（如 React 渲染出错导致白屏，信息只在浏览器控制台），并写明修正后是否需要手动刷新。引用的报错原文按读者实际使用的系统语言实测，不凭记忆翻译。排错示例在读者实际使用的工具链下实测，不换用其他服务器或打包器；并分“开发服务运行中修改并保存”和“刷新页面后加载”两种情况核对页面表现，热更新失败时页面可能保持修改前的样子，刷新后才出错。依赖控制台警告的排错示例，要提示“没有看到时刷新页面再试”，因为部分开发警告每次页面加载只出现一次。控制台连续输出相同内容时，浏览器可能合并为一行并显示次数，描述点击输出时不写“每点一次一行”。只在首次渲染时使用的初始值（如状态的初始值）在开发服务运行中修改并保存，热更新可能保留旧状态，需提示刷新；修复“直接修改状态”这类不触发更新的排错示例后，也提示刷新。

- **版本与环境要求**：写明运行所需的最低版本及来源。文中固定的版本号须实测，未实测的在交付说明中列为未验证项。

- **分步操作的中间状态**：分步保存时，中间页面与最终结果不同（例如样式尚未加入），在步骤处写明，结果核对也包含该步骤造成的可见变化。只用于对照、不需要写入文件的代码，在前文注明“仅作对照，不需要修改文件”，避免读者误改已有文件。

- **标签选择与前文一致**：只用于排列或统一样式的外层使用通用容器，`section` 等语义标签须有对应的内容含义（如标题），并与前文已讲的语义化说明一致。

- **课程独立与数据一致**：课程之间是否独立以作者定位为准。独立课程不互相引用，不设对其他课程的前置要求，所需的资料和配套环境由本课程自带。只有同系列内或确实共用同一份数据时，才逐项核对字段、类型和格式（例如金额是字符串还是数字）；前篇教的写法在后篇数据类型变化时会失效的，提前给出提示。

首次配置虚拟环境时写明激活目录、依赖安装与运行命令；后续沿用系列约定，不用完整解释器路径代替激活步骤。平台写法见 [Python 教程](python-tutorials.md)。

用户明确要求安排视频工作量时，按给定时长和实际讲解、演示、验证与调试负担估算；未要求时不预设时长或调试预算，不靠省略操作与结果标准压缩篇幅。估算留在对话中。

## 人工截图

- 写作或审查实战教程时，只标注能直接证明本节核心能力、关键变化，或仅靠文字难以判断结果的**重点截图**。截图可以来自**网页、终端、SQL 客户端、浏览器网络面板（Network）**及控制台，按证据选择界面，不要求每种界面都配图。普通启动、清空、重启、边界和错误检查默认保留操作及核对说明，不逐项标注截图；它们本身是本节教学重点时再选择配图。检查项不等于截图任务，不将完整验收清单逐项转换为截图清单，不为截图增加无关操作。
- 默认由人工执行操作并截图。正文先写清操作入口、输入、执行顺序与核对标准，仅在选定的重点操作或结果旁用独立的 HTML 注释标记待截图点。标记包含本文内唯一编号、截图界面、具体操作、必须保留的内容及预期结果；不写成学员可见的“待补截图”等制作说明，不插入指向不存在图片的占位链接。例如：

  ```html
  <!-- 待截图 S01 | 网络面板 | 操作：提交首问后打开该请求的 Payload | 保留：question 与 history 字段 | 核对：history 为 [] -->
  ```

- 标注完成后，必须在对话中报告精简的重点截图清单：文档路径及章节或行号、操作步骤、截图界面、必须保留的关键内容和预期结果。区分已覆盖的重点与仍需人工补图的位置，合并能共同说明同一重点的证据；不把无需配图的普通检查混入截图任务。待截图标记与待补清单按编号逐项对应；仅要求审稿时只报告重点位置，不修改文件添加标记。
- 为选定的重点使用实际界面能核对的证据：请求历史或接口状态应展示网络面板或相应响应，SQL 条件应展示执行语句及必要结果，终端验证应保留执行命令和完整关键输出。普通查询成功图不能证明未显示的行为，但不能因此给所有边界补图；没有配图的普通检查保留文字核对步骤，不宣称已被截图证明。
- 人工操作与截图能够完成教学验收时，不在正文另加 `verifyxx.py` 等临时验证脚本，也不将后台自动检查当作人工运行效果的替代。脚本本身属于教学目标或用户明确要求自动化测试时除外。作者侧必要的技术核对仍可进行，但运行记录留在对话或协作文件中；没有实际覆盖的分支不能宣称已经通过验证。
- 人工提供截图后，核对操作、对象、字段与结果是否对应，关键文字和表格是否清晰完整；符合要求后插在标记所在位置并移除该标记，同步相关文档和图片引用。已有图片充分覆盖时直接复用，不重复索要；不以无关旧图、生成图或改写结果代替真实运行截图。截图旁只保留读者需要的解释，不增加截图来源、制作经过或交付状态。
