# 禁用词与替换表

分六组。A–C 是通用的；D 是项目专有（按项目配置）；E 是空话套话；F 是排版。

## A. 内部用语（面向录制/内部流程）

| 禁用 | 替换 / 处理 |
| --- | --- |
| 讲解点： | 说明： |
| 带敲提示： / 手敲提示： | 提示： |
| 讲解 3~5 分钟 / 本节讲 X 分钟 | 删除（属制作信息） |
| 不敲 / 可敲可不敲 | 按语境改写为任务范围或交付方式 |
| 本集（指录制集数）| 本节 / 第 N 节（指文档章节） |
| 节奏模板 / 时间轴 / 计划时长 | 删除 |
| 内部参考 / 内部稿 / 内部文档 | 删除 |

脚本规则源：`default-rules.json`。高置信度内部用语会报 ERROR；“不敲”“本集”等依赖上下文的表达只报 WARN，避免机械误判。

## B. 口播腔（说给在场者）

| 禁用 | 替换 / 处理 |
| --- | --- |
| 我们 / 咱们 / 大家 | 删，或改"本节 / 读者 / 系统" |
| 来看 / 看一下 / 注意看这里 | 直接陈述 |
| 这个很简单 / 很简单 / 其实 | 删 |
| 你会发现 / 可以看到 | 改陈述句 |
| 好，那么 / 接下来我们 | 删 |
| 记住 / 一定要记住 | 注意 / 要点 |

脚本规则源：`default-rules.json`；命中只作 WARN，需结合语境审阅。

## C. 人称代词（正文）

正文优先避免直接称呼读者（你 / 您）和口述者（我 / 我们），改用中性主体（本节 / 该字段 / 系统 / 读者）。第三人称按文体判断，不作机械替换。

**豁免**：代码块内、Markdown 引用块（`>`）、数据/评价原文、示例对话。为让检查器识别豁免内容，将引用排成引用块，或在项目配置中用 `allow_line_patterns` 标记数据行（默认包含 `INSERT ... VALUES`）。

脚本默认正则：`[你我您]`。脚本只做提示，不判断上下文语义。

> 说明：第三人称在正式说明中通常有正常用途，不纳入默认机械扫描。

## D. 内部产物引用（项目专有）

不同项目有不同的内部术语。正式文档面向读者时，应判断这些术语是否可访问、是否有解释，以及是否对读者有用；不应把所有项目路径或来源引用一概删除。

处理：删除无用的内部称呼，或改为读者可理解的名称；保留有用且可访问的项目相对路径。这类禁用词**逐项目配置**，不要写死在通用规则里。

## E. 去 AI 味 / 空话

检查：值得注意的是、综上所述、总而言之、不难看出、需要指出的是。命中后先判断是否为空话，不要无条件删除。
减少：emoji、连续感叹号、整段加粗（加粗只给真正的关键点）。

空话套话仅作为人工审阅提示，避免把有效的论证连接词机械删除。

## F. 排版

| 检查 | 规则 |
| --- | --- |
| 中英文/数字间距 | `约 75 行`、`第 5 节`、`app/models` 保留空格；代码内不加 |
| 标点 | 中文用全角 `，。：；`；代码/英文用半角 |
| 引号 | 全文统一（推荐成对中文引号或统一直引号），不混用 |
| 代码块 | 代码片段标注语言；纯文本示意可标注 `text`；围栏成对 |

## 项目配置 `.formal-docs.json`

通常放在项目根目录；脚本会从文档目录向上查找最近的配置文件。也可通过 `--config` 指定；指定后只读取该配置，不再自动发现其他配置。

```json
{
  "banned": ["仅内部使用的模块名", "对照版"],
  "allow_line_patterns": ["INSERT INTO", "VALUES \\("],
  "space_check": false,
  "numbered_headings": "auto",
  "first_heading_number": 1
}
```

* `banned`：项目专有禁用词（对应 D 档）。
* `allow_line_patterns`：这些正则命中的行，跳过人称检查（如数据行）。
* `space_check`：是否启用中英文空格检查（默认关，噪音较多）；`--space` 可强制开启，`--no-space` 可强制关闭。
* `allow_line_patterns` 只豁免人称检查，不豁免内部用语或项目禁用词检查。
* `numbered_headings`：`auto` 根据首个一级标题判断是否检查编号，也可设为 `true` / `false`。
* `first_heading_number`：文档节选从非第 1 节开始时，设置预期的首个编号。

检查范围：文字围栏（如 `text` / `markdown`）会进行文字扫描；代码围栏会跳过。脚本不会自动识别密钥、验证链接/文件路径或判断语气，相关内容需人工复核。
