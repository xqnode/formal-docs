# 示例验证

本文件用于日常写作、修订和审稿的技术核对，不触发多代理复审。

只核对当前任务相关的下列项目。用户输入错误与服务故障分开描述，统一对外提示时仍保留维护者可定位的异常类型与日志。

检查器不验证技术正确性。可运行示例优先在隔离本机环境实跑，沿用项目验证脚本；没有本机条件时可使用不涉及敏感数据的独立在线实验。不要为写作执行生产写库、部署或其他超出授权的动作。

按正文说明拼装增量示例并整体运行；需要使用验证脚本时，从正文逐字提取代码块，而不是另写一份，这样改过正文后重跑即可发现不一致。每个中间步骤的页面或输出也要核对。核对运行条件、成功输出与失败路径；文字教程安排了练习时，再核对练习和答案。断言选可控的量，区分固定结果、无序集合、倒计时和其他非确定性字段。修改版本要求前用目标版本验证；未执行或未验证的环境写清限制，不声称通过。

完成前人工核对以下对应关系：

- 排错、小结与图解中出现的键名、路径、命令、字段、示例值，来自本篇可见材料、明确定位的前篇，或已完整说明的新示例。
- “本篇练习”“前面已创建”“已有接口”等表述与实际文件、正文和练习相符；跨篇材料标明篇名或编号及位置。
- 新失败示例写清输入、前提与结果，不因某标识首次出现在排错段就直接判错。示例改动了成对的括号或花括号时，恢复说明给出完整的正确片段，或指回原代码位置，不只写“把 X 改成 Y”，也要说明替换的是哪一段。排错示例要求替换的范围（整个函数、函数体、某一行）与代码块实际包含的内容一致；按错误范围粘贴也能产生相同症状时，必须写准。
- 正文中“本节不会……”“数据不会变动”这类范围断言，与本节自己的核对步骤逐条对照，避免前后矛盾。
- 代码、预期输出、练习要求与答案对同一状态变化给出一致结果；图中节点、箭头、分支和正文一致。
- 前端示例允许同一操作在前一请求结束前再次触发时，核对响应乱序的结果：较早请求不能覆盖当前对象的内容、错误提示或加载状态。用可控的完成顺序验证；若交互已阻止请求重叠，不额外加入状态管理。
- 审查课程规划或目录时，逐项列出每个数据字段和数据来源（本地常量、接口、地址栏等）在哪一节引入、在哪一节改变，并记录字段的类型和后续会遇到类型变化的位置（例如数字编号与路径参数的字符串）；每节的结果核对只依赖该节及之前讲过的内容。
- 正文中“出现的就是这条提示”“实测得到”“验证环境中”这类观察性断言，须有实际运行记录（环境、版本、输入与原始结果）。已有记录与当前代码、命令、依赖和相关环境一致时可复用，注明来源与适用范围，不把历史记录写成本轮执行。新增或修改的行为、相关环境变化、记录缺失或与现象矛盾时重跑受影响范围及必要回归；不因只改文字或开始独立审稿就重复搭建环境、安装依赖、执行全量验证。无记录且无法验证的，改成条件说法或列入未验证项，不凭印象认定通过。
- 评估篇幅或是否拆分时，按 Unicode 字符统计并把正文与代码块分开算，不用按字节计数的命令；先看正文量和读者在哪一步第一次看到可见结果，再决定拆分，拆分后的每一半都要有各自可核对的结果。

平台重置、输出格式、批量上限等受环境影响的结论须实测；在对话验证记录中说明日期、平台和可获得的版本，未知版本如实说明。不为稳定命令一律加日期，也不将运行记录写进学员正文。
