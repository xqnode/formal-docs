# 课程复审到发布：参考流程

用于同时维护课程笔记、逐节源码与下载版本时，帮助复审后提出下一步建议。它不是默认写作流程或强制检查清单，也不因读取本文件而启动子代理、运行验证、改源码、提交或发布。普通文章和局部修订只采用相关部分。

## 如何提出建议

复审后先说明当前阶段、已核实的问题与已有验证，再建议一个与问题相关的下一步，例如“先改笔记”“从上一节最新版本做临时迁移验证”“将已验证增量同步源码”。没有实现问题时，不为套流程要求重新跑完整端到端。

执行范围沿用用户已有授权；已授权连续推进时直接推进到约定停止点，不逐步重复确认。仅授权审稿、改文档或临时验证时，分别停在对应范围；后续阶段只是建议。未授权的教学或业务取舍仍由作者决定。

## 可按需采用的五个阶段

| 阶段 | 参考做法与交付 |
| --- | --- |
| 1. 复审 | 明确上一节最新代码、本节笔记与源码范围。显式复审按 [复审](review-loop.md) 分工检查技术衔接、理解断点、图解和注释，先交付问题与最小方案。模型配置只在复审文档维护。 |
| 2. 修改文档 | 按已确认问题修改笔记、图解和必要注释，交回原审稿者针对性复核；保留已确定的教学顺序，不把文档授权扩展为源码修改。 |
| 3. 临时迁移与验证 | 从上一节最新发布标签或已确认提交创建隔离副本，按笔记原文应用增量，保留前节修复。按 [示例验证](example-validation.md) 检查本节链路、接口、数据与模型调用及相关失败边界；发现问题先在副本最小修复并重验。 |
| 4. 同步已验证成果 | 获得源码同步授权后，将验证通过的增量同步到对应带敲源码、笔记、注释和图解。核对与验证副本一致，保留独立章节快照；当前工作区含后续功能时合并相关改动，不用前一节整包覆盖整个项目。 |
| 5. 提交与发布 | 在明确授权范围内提交推送，更新本节标签、Release、下载入口及线上笔记。核对实际下载包、标签提交与线上正文和图片；保护其他课时、视频、权限及尚未发布的章节。仅提交或仅发布笔记时不扩展范围。 |

## 迁移、截图与发布的边界

- 起点按实际版本确定，旧的本节快照可能缺少后来修复的前节代码；不能仅凭节次较新就整包替换。章节独立快照不等于提交或发布授权。
- 临时运行使用隔离数据和索引，真实调用与故障注入分别记录。不把测试包装、临时凭据或数据写回正式源码；结束后关闭自启临时服务、清理凭据，保留必要源码与验证证据。
- 截图按作者约定完成。集中截图时，本地保留必要位置、输入操作和结果核对点，不因占位标记宣称已有截图；线上内容不展示内部待截图标记，不用其他节次效果替代本节结果。
- 推送前检查待推送的提交范围，不能只检查暂存文件；已有未推送提交或后续章节不自动纳入。下载版本只包含截至本节的完整代码，不能直接把含后续功能的当前主线当成本节结束代码。
- 同步后若代码行为与验证副本一致，可复用已有运行证据并补做受影响检查；逻辑或环境变化时再跑相关回归。交付区分本轮实跑、历史证据和未验证项，制作记录不进入学员正文。

本参考不要求一次推进所有章节，也不把阶段完成视为下一阶段的授权。按当前授权交付成果，并可说明建议的下一步。
