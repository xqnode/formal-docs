# 复审

## 范围与权限

- 本流程独立于默认写作流程。仅在用户明确要求“复审”、要求多代理审改闭环，或本任务已有该闭环的明确授权时加载执行。
- 新写完整文章、系列续篇、普通整篇审稿或交付本身不触发本流程；单独指定某个代理审查时仅执行指定范围，不自动启动整个闭环。
- 局部补充、措辞、标点或格式修订：只查受影响段落、引用、示例及必要回归，不另派全篇审稿代理。
- 仅要求审稿：独立检查后交付问题清单，停在报告；不自动修改、添加截图标记或进入修订循环。
- 已授权修改：只处理确认的问题及必要同步；改变教学顺序、课程范围、技术或业务设计的未定取舍须交作者决定。审稿通过不授权改源码、提交、推送或发布。

先明确目标读者、已有知识、前篇、当前文档与对应代码版本。按项目已有约定判断，不把“入门”或章节靠后当作省略讲解的依据。

## 按职责加载材料

主代理加载本流程与本次涉及的参考小节。技术审稿者读取技术与教学审查职责及原始材料；专项审稿者读取图解与注释职责、[图解规则](diagrams.md)和[条件分支注释](structure-template.md#条件分支的教学注释)。不要求每个代理通读全部参考文件。

首次独立审稿使用不继承写作对话的会话或子代理。任务交接提供职责、文档与图片路径、项目规范、读者基础、大纲、相关前篇、对应源码与必要运行材料的入口；不预先提供写作者或其他审稿者的候选问题、结论或验证总结。先形成独立判断，再核对既有证据。

审稿代理只读不改，不继续委派。后续针对性复审可以沿用原审稿者，不要求再次隔离它自己已发现的问题。指定配置或独立会话不可用时，明确说明哪部分未完成，不静默替换或将自检称为独立审稿；用户指定配置优先。

## 首轮审查的宿主配置

### Codex：三轮职责

1. **机械审查**：主代理以 skill 目录为基准运行 `scripts/check_notes.py`，核对格式、项目规范、路径、命令、示例值与前后文一致性；不强制另派代理。
2. **独立技术与教学审查**：`gpt-6-astra`，推理程度固定 `low`，不继承写作上下文。
3. **图解与代码注释专检**：`gpt-6.1-sol`，推理程度固定 `low`，不继承写作上下文。

第二、三轮可以并行，轮次表示职责；各自不接收其他审稿者的候选结论。Codex 不套用“审稿比写稿高一档且不低于 high”的规则。

### Claude Code 与其他非 Codex 宿主

保留原有两轮：第一轮使用检查器和低成本模型进行机械核对；第二轮在独立会话或不继承写作上下文的子代理中进行技术与教学审查。另行安排图解与注释专检，可与第二轮并行，不能替代第二轮。

第二轮从用户已有可用模型中按准确性和预算选择，默认思考程度 `high`；已知写稿档位时，在所选模型支持的顺序内比写稿高一档，且不低于 `high`。写稿档位未知时使用 `high`；不支持该档或已到最高档时使用最高可用档并注明限制。不同模型的档位不作能力等价比较，不改变用户全局设置。

Claude Code 专项检查默认使用 **Haiku 子代理**，思考强度沿用模型默认；其他宿主使用其明确支持的低成本执行模型。

## 各项审查检查什么

### 机械核对

核对正文标题（包含 ATX、Setext、HTML H1）、标点、人称、禁用词、围栏语言、编码、链接的可访问性与实际语言、路径、命令、字段类型和项目规范。修复有效 ERROR，WARN、INFO 结合语境判断，不追求机械清零。检查器能力与参数见 [配置说明](banned-phrases.md)。

对命令输出、报错原文、端口、版本与默认行为等观察性断言，区分已有运行依据、可以重跑和只能由读者环境验证的内容；检查器通过不能证明这些事实。

### 技术与教学审查

逐段检查技术含义、代码与正文一致性、版本前提和增量操作完整性。按目标读者逐步推演：是否知道在哪里输入、数据从何而来、谁调用谁、怎样处理、输出给谁，以及如何判断成功和排错。必要处结合具体数据讲输入、处理与输出，不能只补术语定义。

核对新增复杂度是否服务当前目标，是否跳过前置知识；对照相邻章节检查重复引入、标题骨架与衔接。沿用既定教学顺序与方案，找出最小解释或操作补充，不以格式合规或代码能运行代替理解效果。具体写法按需查 [结构参考](structure-template.md) 与 [课程笔记](course-notes.md)。

### 图解与代码注释专检

检查调用顺序、数据流、分支、状态与模块关系是否需要图解，以及已有图片的文件、正文引用、节点与方向是否一致。按 [图解规则](diagrams.md) 查看实际渲染，检查文字可读、箭头及标签不遮挡；字符图、占位和 SVG 能解析不等于图已合格。无法渲染列为未验证，不按图的数量验收。

遍查全部代码块，重点查图编排、条件边、非显然常量、数据来源、过滤去重、失败及资源清理路径。按 [条件分支注释](structure-template.md#条件分支的教学注释) 判断用途、规则、原因和处理是否讲清；正文不能替代必要代码内注释。简单导入、赋值和已解释的重复逻辑无需逐行注释，不按覆盖率验收。

本闭环中的专项检查按以上职责执行；用户只要求专项审查时，按主文件的范围规则执行，不据此展开本闭环。

## 核实、修改与复审

1. **形成问题清单**：每条给出文件与行号或图路径、触发条件、实际影响及依据；分为已确认错误、解释不足、可选增强、未能验证。不凑数量，允许没有问题；输出前尝试反驳候选问题，无法排除合理反例的标为存疑或删除。
2. **主代理核实**：回到规范、源码和运行材料逐条核实，合并重复项，剔除误报，按读者影响排序。替代代码的相关行为也要验证，不能凭印象提出修复。
3. **最小修订**：在已有授权内修复必改项，同步受影响代码示例、注释、图解与引用，不为可选增强扩张主线。未定方案先交作者选择，等待期间继续不依赖该选择的检查。
4. **针对性复审**：把已核实问题、修改位置与有关依据交回原审稿者，只复核其负责的问题、变动及必要回归。专项代理只复查相关代码块和图片。无需每次重启整篇独立审稿。
5. **有问题则继续**：若修改未解决问题或引入新必改项，修订后再复核对应范围。同一问题反复出现或审稿意见冲突时，主代理依据原始材料裁定；缺少教学或业务取舍时请作者决定，不无限重复派审。

## 停止条件与交付

已确认的必改项全部解决，针对性复审未发现新的必改项，受影响的机械检查、示例与图解验证通过，才结束本轮闭环。条件不足时说明剩余问题或验证限制，不宣称全部通过；仅审稿任务按范围要求停在清单。

目标不是“任何审稿者都提不出建议”。有依据排除的误报、未采纳的可选增强不阻止结束，不为清零意见无限补解释、图或边界处理。没有发现问题不等于保证没有问题。

交付简述修改文件、实质变化、验证依据与未验证项，以及审稿执行者、模型、可获得的档位和独立性；局部修订说明只做局部检查。截图待补清单遵循课程笔记，工作量仅在用户要求时报告。审稿与运行记录留在对话或协作文件，不进入学员正文。

## 验证要求

复用 [示例验证](example-validation.md) 的相关要求；复审不因重新开审而重复搭建环境或执行全量验证。

课程复审后如需规划临时验证、源码同步或发布，可按需查阅 [课程复审到发布参考](course-review-to-publish.md)，只建议与当前问题和授权有关的下一步，不自动执行后续阶段。
